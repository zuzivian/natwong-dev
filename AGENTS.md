# AGENTS.md — rules for OpenAI Codex (and other coding agents)

Read this, then `NOTES.md` (checks, done / next / gotchas), then `README.md`.

## What this project is
natwong.dev is Nat Wong's personal portfolio: one static page (`index.html`) that positions him
as a product manager for aerospace, defense and AI. Vercel deploys `main`. Brief for this repo:
quality work only (accessibility, performance, checks, docs); no bio, resume or personal-copy
changes, and no new pages.

## Hard constraints
- Static site, no build step. Do NOT add a root `package.json` (Vercel would treat the site as a
  Node build).
- Everything in the repo root is publicly served, including `README.md`, `NOTES.md`, `scripts/`
  and `.github/`. Never put anything private there.
- `/resume.pdf` stays unlinked and noindex (`vercel.json`). Never link it from the page,
  `sitemap.xml` or `robots.txt`; `scripts/check.py` enforces this.
- Do not edit the bio, resume, headline or any personal copy; do not touch `resume.pdf`,
  `LICENSE`, `vercel.json`, `.github/workflows/` or other deploy/infra config.
- Do not add dependencies or bump the SHA-pinned workflow actions.
- Never write passwords, tokens or account numbers anywhere, including PR text.
- Never skip or delete checks to get green.

## How to work
- One small, scoped change per PR (1-2 hours of work, a diff a person can review in minutes).
- Branch from the latest `main` as `codex/<short-topic>`. Never push to `main` or to someone
  else's branch.
- Before starting, list open PRs and read their changed files. Do not touch files an open PR
  changes; if your task needs them, stop and say so in the PR body.

## Checks to run before opening a PR
1. `python3 scripts/check.py` (standard library only; CI runs it on every push and PR). It
   must pass.
2. For visual changes: `python3 -m http.server`, then load the page at 1280 px and 390 px wide:
   no console errors, no horizontal scroll, layout unchanged except for what the task names.
3. `git diff --stat` shows only the files your task names.
If a check cannot run in your environment, say so; do not claim it passed.

## Pull requests
- Open a DRAFT PR into `main`. Short imperative title. Reference the issue (`Closes #N`).
- Never merge, never enable auto-merge, never force-push. A person reviews and merges.
- The PR body must end with a "Verified" section: exactly which checks you ran, what you saw,
  and what you could not verify. Then end with:

```
---
_Generated by OpenAI Codex_
```
